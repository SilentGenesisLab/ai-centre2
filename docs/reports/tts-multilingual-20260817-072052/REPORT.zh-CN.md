## 七、方法与边界

- 参考音频由同一套生产VoxCPM2先生成，再上传到生产OSS，避免依赖来源不明的外部样本。
- 同语言克隆提供准确参考文本；跨语言由控制面自动识别语言并路由到隔离Reference/Controllable模式。
- CER/WER来自ASR，因此会包含ASR自身误差；报告同时保留控制面门禁CER用于交叉核对。
- 矩阵覆盖组主要用于发现语言兼容性问题；并发性能组每格20次，专用于P95/P99和吞吐统计。
- 资源数据按1秒采样，CPU为systemd cgroup增量，包含子进程；显存和GPU数据来自nvidia-smi。
- 本次测试不会改生产配置，不会真实执行GPU启停，也不会在报告中保存Token或OSS密钥。

## 八、结论分析与根因

### 8.1 无参考音频

- 126次无参考请求的原始逐字一致率为93.7%，平均CER为0.0244；中文性能组60/60完全一致。
- 中文中等文本并发1/2/4的P95分别为0.65、0.64、1.17秒，吞吐分别为0.887、1.860、2.110请求/秒。
- 德语、俄语和阿拉伯语长文本的非完全一致主要是ASR拼写或变音符号差异，CER分别只有0.0080、0.0028、0.0071，并非明显丢句。
- 日语短句“お帰りなさい”生成了1.12秒、RIFF完整的音频，但当前Faster-Whisper日语复核返回空文本，控制面门禁也判定失败。仅凭本次自动测试不能区分“日语短句生成异常”和“短日语ASR失效”，因此日语短句暂不应标记为生产通过。

### 8.2 同语言深度克隆

- 126次同语言克隆原始逐字一致率仅4.0%，平均CER为0.5615；CAM++均值却达到0.868。
- 中文并发性能组60/60都出现参考尾句前插，典型转写为“清晰而稳定的语音表达＋目标正文”；短句样本为“清晰而稳定的语音表达＋欢迎回来”。
- 根因是同语言自动路由到`ultimate`后，参考音频被VAD选择为4～6秒窗口，但送入continuation的`prompt_text`仍是完整参考文本，文本与裁切后的音频不对齐。模型先续完参考文本尾部，再合成目标正文。
- 门禁不是漏检：同语言克隆门禁通过率为0%，绝大多数被准确标记为`content,prefix,speed`并执行三候选重试。问题在于既定策略要求三次失败仍返回最佳候选，因此客户端只看HTTP 200会收到已知不合格音频。
- 高CAM++同时伴随严重内容错误，证明说话人相似度只能在“正文与首尾门禁先通过”后参与排序，不能单独代表可交付质量。

### 8.3 跨语言克隆

- 166次跨语言克隆原始逐字一致率89.8%，平均CER为0.0425，CAM++均值0.564；中等长度98%逐字一致，长文本6/6完全一致。
- 西班牙语→中文共66次全部正文完全一致；专门性能组并发1/2/4均为20/20准确，P95分别为1.21、7.77、2.41秒。并发2的长尾具有明显偶发性，不能据此认为并发4天然快于并发2。
- 英语、法语、日语、俄语参考→中文中长文本，以及中文→英语、西语、法语、德语、韩语、俄语、阿语，正文整体稳定。
- 德语/意大利语/韩语/阿语参考→中文短句被ASR写成繁体“歡迎回來”，与目标简体“欢迎回来”语义等价，却被字符门禁判为前缀和CER=0.5；这12条不是真实的额外发声。门禁应增加简繁等价归一化。
- 中文→日语的短中句存在日语ASR书写差异或识别失败，需要日语专项盲听和第二套ASR复核。
- 内容完全正确但CAM++门禁失败的主要语言对包括英语→中文、葡语→中文、中文→德语和部分中文→俄语。当前CAM++模型为中文`zh-cn`版本，跨语言分数不能直接使用统一阈值解释。

### 8.4 长度影响

| 模式 | 短文本：准确率 / CER | 中等文本：准确率 / CER | 长文本：准确率 / CER |
| --- | --- | --- | --- |
| 无参考 | 90.9% / 0.0909 | 97.6% / 0.0006 | 72.7% / 0.0016 |
| 同语言克隆 | 9.1% / 1.4224 | 2.4% / 0.2744 | 0% / 0.1188 |
| 跨语言克隆 | 75.0% / 0.1167 | 98.0% / 0.0005 | 100% / 0 |

长文本“完全一致率”容易被单个ASR拼写差异拉低，因此应结合CER判断。真正最危险的是同语言克隆短句：参考尾句相对目标正文占比最大，平均CER达到1.4224。

### 8.5 资源与容量

- RTX 5090峰值利用率94%，峰值显存25824MiB，约保留6783MiB显存余量；峰值功耗360.76W、最高60℃，没有发现显存溢出、过热或服务重启。
- VoxCPM2 cgroup内存峰值4434.73MiB，控制面峰值207.84MiB，CAM++峰值969.19MiB。
- CAM++ CPU峰值202.54%，并发下仍会形成质量校验长尾；ASR复核运行在GPU0，其资源占用不应计入TTS GPU1模型本身。
- 测试结束后VoxCPM2、兼容网关、控制面、CAM++和ASR服务均保持`active`。

## 九、生产建议与优先级

1. **P0：修复同语言Ultimate参考对齐。** Ultimate必须使用与参考音频窗口逐字对齐的文本；可以对选中的4～6秒窗口重新ASR，也可以在有准确整段`prompt_text`时保留整段参考音频。禁止将裁切窗口与整段文本混用。
2. **P0：增加失败后的Controllable回退。** 同语言Ultimate三候选出现`content`或`prefix`失败时，自动再走一次隔离Reference/Controllable；仍遵循“不返回502”，但返回的是正文正确的降级候选，并设置`X-TTS-Clone-Fallback: ultimate-quality-failed-controllable`。
3. **P0：客户端必须读取质量头。** 在修复完成前，`X-TTS-Quality-Passed=false`不能作为正常音频交付，即使HTTP状态是200。
4. **P1：完善多语言等价归一化。** 中文加入简繁转换；日语允许常见汉字/假名等价；俄语、阿语处理不影响发音的附加符号，避免把ASR正字法差异当成额外发声。
5. **P1：更换或校准跨语言说话人门禁。** 当前中文CAM++对英语→中文等语言对明显偏低，应使用多语言说话人模型或建立按语言对校准的阈值；正文和首尾异常门禁仍保持最高优先级。
6. **P1：优化CAM++并发。** 缓存参考音频embedding，并使用受控工作池处理候选embedding，降低偶发7～9秒P95长尾。
7. **P1：日语专项复核。** 使用第二套多语言ASR并对短句进行人工盲听，确认是生成器问题还是当前Faster-Whisper短日语识别问题后再开放日语短句。

当前生产可用性结论：**无参考中文/英语等主要语言可用；跨语言中长文本内容能力总体可用，但音色门禁需按语言对校准；同语言Ultimate克隆暂不满足生产交付标准。**
