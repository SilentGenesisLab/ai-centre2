# 精准标题/字幕检测与擦除模块 Spec

版本：1.0  
适用范围：竖屏营销短视频，主要语言为泰语、西班牙语、葡萄牙语、英语和中文。  
目标：准确输出顶部标题和底部字幕的文字事件、稳定区域及擦除/覆盖方案，同时避免处理产品包装、Logo、Emoji、水印和其他画面文字。

## 1. 核心原则

1. OCR 原始框只是候选，不能直接作为擦除框。
2. 先进行单帧文字分组，再进行跨帧轨迹与事件判断。
3. “字幕位置轨道”和“字幕文字事件”必须分开：
   - 位置轨道描述字幕通常出现在哪里、使用多大区域。
   - 文字事件描述某段文字从什么时候开始、什么时候结束。
4. 标题与字幕分别处理：
   - 标题位于画面上半区，通常在一个分镜内持续存在。
   - 字幕位于画面下半区，通常跟随语音变化。
5. ASR 用于确认字幕时间和补偿 OCR 漏帧，不允许仅凭 ASR 在没有视觉文字证据的位置创建擦除框。
6. 色块只有在内部或邻近位置存在有效文字证据时，才能判定为标题/字幕色块。

## 2. 坐标约定

视频宽高：

```text
W = frame_width
H = frame_height
```

OCR 框：

```text
[x1, y1, x2, y2]
box_width  = x2 - x1
box_height = y2 - y1
box_cx     = (x1 + x2) / 2
box_cy     = (y1 + y2) / 2
```

居中值：

```text
center_ratio = (x1 + x2) / W
```

完全居中时 `center_ratio = 1.0`。

默认候选范围：

```text
标题：0.86 <= center_ratio <= 1.14
字幕：0.90 <= center_ratio <= 1.10
```

其中字幕范围意味着文字中心距离画面中心不超过 `0.05W`。

## 3. 区域定义

默认将画面划分为：

```text
标题候选区：0.03H <= box_cy < 0.48H
中间灰区：  0.48H <= box_cy < 0.52H
字幕候选区：0.52H <= box_cy <= 0.95H
```

规则：

- 上半区最多保留一个标题/CTA 轨道。
- 下半区最多保留一个字幕轨道。
- 中间灰区候选只有与相邻帧既有轨道匹配时才能加入。
- 同一帧最多生成两个处理区域：一个上部区域、一个下部区域。

## 4. 30 FPS 视频采样策略

### 4.1 推荐采样率

30 FPS 视频的默认 OCR 扫描频率：

```text
常规 OCR：每 0.2 秒一次，即每 6 帧一次，约 5 FPS
变化复核：每 1～2 帧一次
稳定降频：每 0.4 秒一次，即每 12 帧一次，约 2.5 FPS
```

不建议全程逐帧 OCR。逐帧 OCR 的计算量约为 5 FPS 扫描的 6 倍，但大部分相邻帧提供的是重复信息。

### 4.2 自适应两阶段扫描

第一阶段为粗扫描：

1. 解码时保留原始帧号和时间戳。
2. 每 6 帧调用一次 OCR。
3. 同时执行低成本的分镜检测、画面差异和已有文字区域变化检测。
4. 输出疑似事件变化点：
   - 新文字出现。
   - 已有文字消失。
   - OCR 文本明显变化。
   - 文字框位置或尺寸明显变化。
   - 分镜切换。

第二阶段为边界精修：

1. 对每个变化点前后 `0.30 秒` 范围重新检查。
2. 30 FPS 下对应前后各 9 帧。
3. 默认每 2 帧检查一次。
4. 对最终出现/消失边界附近再逐帧确认。

推荐精度：

```text
普通模式：事件边界误差 <= 2 帧，约 66.7 ms
高精度模式：事件边界误差 <= 1 帧，约 33.3 ms
```

### 4.3 什么时候提高采样率

出现以下任一情况时，从 5 FPS 临时提高到 15～30 FPS：

- 分镜切换前后 0.3 秒。
- OCR 候选由无变有或由有变无。
- OCR 文本相似度低于 0.75。
- 候选框 IoU 低于 0.60。
- ASR 检测到说话开始或结束，但字幕轨道状态尚未改变。
- OCR 置信度低于 0.70。

### 4.4 什么时候可以降低采样率

同一标题轨道满足以下条件持续 1 秒后，可降至 2.5 FPS：

- 位置 IoU 大于 0.85。
- OCR 文本相似度大于 0.90。
- 框宽、框高变化均小于 5%。
- 当前没有分镜切换。

底部语音字幕不建议低于 5 FPS，因为短字幕事件可能只有 0.5～1 秒。

## 5. 单帧文字候选过滤

### 5.1 基础过滤

下列 OCR 框默认不作为标题/字幕候选：

- `box_height < 0.018H`，除非它能与其他行组成有效多行字幕。
- 旋转角度绝对值大于 8 度。
- OCR 置信度低于 0.45。
- 位于画面四角且跨多个分镜长期不变。
- 与产品包装区域共同运动、旋转或缩放。
- 同一小区域内存在 5 个以上密集小字框，疑似包装说明文字。

### 5.2 包装、Logo、Emoji 保护

以下内容不进入擦除轨道：

- 产品瓶身、包装盒和说明书上的小字。
- Logo、品牌标识和长期水印。
- Emoji、警告图标、箭头、折扣贴纸中的纯图形部分。
- 非水平排布、明显透视或跟随实体物体运动的文字。

如果文字框与保护区域 IoU 大于 0.30，应降低候选分数；IoU 大于 0.60 时默认拒绝。

## 6. 多行文字分组

不能用“各行宽度差异小于 20%”作为硬条件。短尾行、泰语换行和标点行可能明显更窄。

两行文字合并为同一组时，应满足：

```text
中心点水平差 <= 0.05W
字体高度比在 0.75～1.33 之间
垂直间距 <= max(20px × H/1920, 0.70 × 中位行高)
水平方向重叠比例 >= 0.50
颜色、描边或背景样式相近
```

宽度差小于 20%只作为加分项。

多行联合框：

```text
group_bbox = union(all_line_bboxes)
```

需要保存每一行的原始框，后续 ASS 排版仍需使用行数、行高和行间距信息。

## 7. 标题、字幕与其他文字分类

### 7.1 顶部标题

典型特征：

- 位于上半区。
- 水平居中。
- 在一个分镜内位置和内容较稳定。
- 通常持续 1 秒以上。
- 可能包含多行文字、描边、贴纸或纯色色块。
- 宽度通常为 `0.30W～0.95W`。

### 7.2 底部字幕

典型特征：

- 位于下半区。
- 水平居中。
- 基线、字号和样式稳定。
- 文本内容随说话变化。
- 单个事件通常持续 `0.4～4.0 秒`。
- 与 ASR 语音活动区间存在明显重叠。

### 7.3 CTA

CTA 可位于上半区或下半区，具有以下特征：

- 较粗字体、描边或高饱和颜色。
- 常包含数字、百分比、感叹号或行动词。
- 可能与 Emoji、箭头、警告标识相邻。
- 相对于画面坐标稳定。

CTA 文字需要处理，但 Emoji 和图形默认保留。擦除区域只覆盖文字联合框及必要描边，不扩展到相邻图形。

### 7.4 分类输出

每个文字组必须输出以下类别之一：

```text
top_title
bottom_subtitle
cta_text
product_text
logo_watermark
unknown_text
```

只有 `top_title`、`bottom_subtitle` 和确认需要处理的 `cta_text` 进入擦除流程。

## 8. 跨帧轨迹

相邻采样中的文字组满足以下条件时，归入同一轨道：

```text
bbox IoU >= 0.50
或中心偏移 <= 0.04W 且基线偏移 <= 0.03H
文字高度比在 0.75～1.33 之间
```

轨迹采用滞回策略：

- 最近 3 次采样中出现至少 2 次，确认轨迹开始。
- 连续 3 次采样均未出现，确认轨迹结束。
- 中间漏检不超过 0.4 秒时，使用前后轨迹插值补齐。
- 分镜切换时结束旧轨迹，禁止跨分镜合并。

标题轨迹与字幕轨迹分别维护，不允许上下区域互相抢占。

## 9. 文字事件切分

同一位置轨道内，以下任一条件满足时生成新事件：

- 规范化文本相似度小于 0.55。
- 行数发生变化，并持续至少 2 次采样。
- OCR 联合框高度变化超过 35%并持续至少 2 次采样。
- ASR 检测到新的语义片段，且 OCR 文本同时变化。

仅 OCR 单帧识别结果不同，不立即切事件。需要跨帧投票，避免识别抖动导致字幕频繁变化。

推荐文本投票：

1. 收集事件内所有高置信度 OCR 文本。
2. 以置信度、持续帧数和文本相似度加权。
3. 选择累计权重最高的文本作为 `source_text`。

## 10. 稳定擦除框

擦除框不能直接使用单帧最大框，也不能使用所有异常框的绝对并集。

对每个分镜内的同一位置轨道：

1. 删除中心位置、宽高偏离中位数超过 2.5 倍 MAD 的异常框。
2. 分别计算 `x1` 的第 5 百分位、`y1` 的第 5 百分位、`x2` 的第 95 百分位、`y2` 的第 95 百分位。
3. 得到稳定框 `stable_bbox`。
4. 在稳定框基础上扩展描边安全边距。

1080×1920 默认扩展：

```text
left/right  = 30px
top/bottom  = max(8px, 0.15 × median_text_height)
```

其他分辨率按比例缩放：

```text
horizontal_padding = round(30 × W / 1080)
```

约束：

- 扩展后仍必须以原文字组中心为中心。
- 上部框不得跨入下半区，下部框不得跨入上半区。
- 擦除框不得因为单次 OCR 误检覆盖大面积产品或人物。
- 每个分镜最多一个上部稳定框和一个下部稳定框。

## 11. 色块检测

色块候选必须同时满足：

- 接近矩形或圆角矩形。
- 内部颜色方差较低。
- 在分镜内相对静止。
- 内部或邻近位置存在有效 OCR 文字组。
- 文字中心与色块中心偏移小于色块宽高的 12%。
- `文字联合框面积 / 色块面积` 在 0.15～0.80 之间。

没有文字证据的纯色区域不能进入处理流程。

色块输出：

```json
{
  "bbox": [100, 80, 980, 360],
  "shape": "rounded_rectangle",
  "corner_radius": 24,
  "fill_color_bgr": [0, 215, 255],
  "confidence": 0.94
}
```

## 12. ASR 联合校验

ASR 用途：

- 校验底部字幕是否与说话时间重叠。
- OCR 短暂漏检时延续已有字幕轨道。
- 辅助判断换句位置。
- 为后续翻译和 TTS 提供语义片段。

ASR 不得用于：

- 在没有任何视觉证据的位置创建标题框。
- 把产品包装文字升级成字幕。
- 决定具体擦除框大小。

字幕事件与 ASR 片段重叠率：

```text
overlap = intersection_duration / subtitle_event_duration
```

默认：

- `overlap >= 0.40`：正常字幕。
- `0.15 <= overlap < 0.40`：降低置信度，保留复核。
- `overlap < 0.15`：更可能是 CTA、标签或非语音文字。

## 14. 调试产物

开发阶段必须支持导出：

1. `raw_ocr.mp4`：显示所有 OCR 原始框。
2. `classified_tracks.mp4`：
   - 顶部标题：蓝色。
   - 底部字幕：绿色。
   - CTA：橙色。
   - 被保护文字：灰色。
   - 未确定文字：紫色。
3. `white_mask.mp4`：只对白名单处理事件覆盖白色矩形。
4. `stable_bbox.mp4`：显示最终稳定框及事件开始、结束时间。
5. `subtitle_events.json`：完整机器结果。
6. `review.html`：原视频与调试视频左右同步播放。

白色 Mask 视频用于检查框是否正确，不代表最终生产渲染样式。

## 15. 模块接口

建议接口：

```http
POST /v1/subtitle-events/detect
```

请求：

```json
{
  "input_path": "D:/videos/input.mp4",
  "source_lang_hint": "es",
  "mode": "balanced",
  "export_debug_video": true,
  "config": {
    "coarse_interval_seconds": 0.2,
    "boundary_window_seconds": 0.3,
    "center_tolerance_top": 0.14,
    "center_tolerance_bottom": 0.10,
    "horizontal_padding_ratio": 0.0278,
    "max_tracks_per_half": 1
  }
}
```

响应：

```json
{
  "job_id": "subtitle-detect-001",
  "status": "succeeded",
  "events_json": "output/subtitle_events.json",
  "debug_video": "output/stable_bbox.mp4",
  "review_html": "output/review.html",
  "metrics": {
    "shots": 8,
    "tracks": 11,
    "events": 27,
    "needs_review": 2,
    "elapsed_seconds": 18.4
  }
}
```

运行模式：

```text
fast:
  常规扫描每 0.30 秒，边界每 2 帧复核

balanced:
  常规扫描每 0.20 秒，边界逐帧复核

accurate:
  常规扫描每 0.10 秒，边界逐帧复核
```

默认使用 `balanced`。

## 16. QA 指标

基准集至少包含 20 个视频，每个视频取 30 秒，并人工标注：

- 标题/字幕真实类别。
- 事件开始帧和结束帧。
- 每个事件的真实联合框。
- 产品、Logo、Emoji 等保护区域。

核心指标：

```text
事件召回率       >= 98%
事件精确率       >= 95%
标题/字幕分类准确率 >= 97%
事件边界平均误差 <= 2帧
稳定框文字覆盖率 >= 99%
保护区域误覆盖率 <= 0.5%
空框率           = 0%
每帧处理框数量   <= 2
```

“空框率 = 0%”表示：生产输出中只要绘制色块，就必须存在对应翻译文字；没有有效翻译时不得擦除原文字。

## 17. 失败门禁

出现以下情况时任务标记为 `needs_review`，不得自动进入最终合成：

- 有稳定擦除框但没有有效 OCR 文本。
- 有擦除框但没有翻译文本或 ASS 事件。
- 翻译文字真实渲染框超出色块。
- 同一帧生成超过两个擦除区域。
- 擦除框与保护区域 IoU 大于 0.30。
- 事件边界无法在 OCR 和时序信息间达成一致。
- 分镜内稳定框面积超过画面面积的 25%，且原始文字面积明显更小。

## 18. 推荐开发顺序

第一阶段：只实现事件检测。

- 输出 `subtitle_events.json`。
- 输出彩色 BBox 调试视频。
- 不执行擦除、不执行翻译。

第二阶段：实现稳定框和白色 Mask。

- 验证标题、字幕是否完全覆盖。
- 验证包装、Logo、Emoji 是否被保护。

第三阶段：实现色块复写和 ASS 回贴。

- 根据事件生成固定色块。
- 标题翻译写回顶部色块。
- 字幕翻译按事件时间贴回底部色块。
- 渲染后检查文字必须完全位于色块内部。

第四阶段：接入现有 ASR、翻译、TTS 和最终音视频合成链路。

每一阶段通过基准集回归后才能进入下一阶段。
